# Qwen3.8-27B runbook — 2026-08-18 (v2)

**Status: new-version profiles, validated pins pending first desktop boot.**
This document supersedes the Qwen3.8 sections of
`new-desktop-install.md` (2026-08-16) for the two **experimental DSpark
profiles**, and updates the MTP gate, evidence, and watch-list for the
whole model. The vLLM BF16 baseline and the SGLang BF16 profile are
**unchanged** — their pins were verified still-current on 2026-08-18
(research receipt:
`docs/research/2026-08-18-qwen38-upstream-update-research.md`).

The 08-16 scripts and this document's `-v2` scripts coexist: old container
names, old `/models` trees, and old env files are never touched by the v2
rollout. Promote a v2 profile only after its validation gate passes and
delete the 08-16 version's section from this document's "superseded" list
in the same change.

## What changed since the 08-16 runbook

Seven upstream developments (research 2026-08-18, receipts under
`docs/research/qwen38-2026-08-18-evidence/`):

1. **vLLM #52469 was a harness artifact, closed `not_planned` 08-16.** The
   "streamed-delta corruption" was the reporter's `grep -o
   '"content":"[^"]*"'` SSE extraction truncating escaped quotes.
   Instrumented verification (3 boots, sequential + 8-way concurrent, chat +
   raw completions): streamed output byte-identical to non-streamed at every
   hop. *Consequence:* dropped from the risk list. If the MTP canary
   survives, it must parse SSE with a real JSON parser (`jq`), never
   grep/regex.
2. **vLLM #52480 (the TP≥2 MTP blocker) is now assigned and actively being
   root-caused** (`jungjiyu`, 08-16): the failing drafter shape `[5120, 4352]`
   is the TP2 NVFP4-packed `down_proj` shape; with the MTP exclusions the
   linears resolve to `UnquantizedLinearMethod` and load fine. No fix PR yet.
   *Consequence:* MTP stays gated off at TP≥2; the gate text now records the
   active investigation.
3. **vLLM #52197 merged 08-17:** DSpark drafts with
   `architectures=["DSparkDraftModel"]` + `model_type="qwen3"` (our draft,
   exactly) are now natively normalized to `Qwen3DSparkModel` in
   `vllm/config/speculative.py` (method auto-detect + architecture rewrite).
   *Consequence:* our launcher's one-field draft surgery is now redundant
   upstream but is retained as an image-independent, idempotent fallback.
4. **New vLLM nightly usable for the DSpark re-pin:**
   `vllm/vllm-openai:nightly-aa9903490c616dc6871e5acc62cec7bb1e5e9434`
   (source commit `aa99034`, 08-18; AMD64 manifest
   `sha256:7eb4028507367e69cb0abfa213042d1814c27c1b499af45fbffec8f16d9cbc6f`).
   Post-dates all of #52197, #52539 (fused GDN MTP kernel for Qwen head
   ratios, 08-18), #50729 (mamba state-copy race fix, 08-17), #50685
   (Qwen3Next sequence-parallel boundaries, 08-14). Still no vLLM release
   contains the GDN spec fixes (#51812/#51674).
5. **Draft checkpoint moved:** `RadixArk/Qwen3.8-27B-DSpark` HEAD is now
   `85ef153be924f17ce4bf62726954eeaa4a73e854` (08-16). Only `dflash.py`
   changed (the reference verify-loop now consumes
   `verify_width = block_size + 1` and slices
   `logits[:, -block_size:, :]` — our 7-gamma / 8-verify geometry); the
   `model.safetensors` LFS object is **byte-identical** (oid `9d26d5e6…`).
   *Consequence:* v2 download re-pins `85ef153` into a separate
   `/models/Qwen3.8-27B-DSpark-v2` tree.
6. **SGLang cookbook reworked (08-14/08-17, PRs #34860/#35065/#35121/#35064):
   the 08-14 URL now 404s.** New reference:
   <https://docs.sglang.io/cookbook/autoregressive/Qwen/Qwen3.8-27B.md>.
   The documented explicit mamba pin is `target_concurrency × S` — **S
   only** (5 for `extra_buffer`); the engine divides the state pool by S
   alone and sizes the speculative verify buffer (D = γ + 1) separately, so
   folding D in over-provisions the GDN state pool and shrinks KV. The
   08-16 launcher pinned `8 × (5 + 7 + 1) = 104`; the cookbook's balanced
   pin at 8 requests is **40**. *Consequence:* v2 SGLang DSpark launcher
   uses `MAMBA_STATE_SLOTS` (default 5) — boot-log `max_running_requests`
   is the acceptance check.
7. **Pi catalog:** `reasoning_effort: "medium"` is a **silent no-op** for

## 5. Experimental Qwen3.8-27B DSpark on SGLang (v2)

**Launcher:** `scripts/inference/qwen38/run-qwen38-27b-bf16-dspark-sglang-v2.sh`
— container `qwen38-27b-bf16-dspark-sglang-v2`, env
`~/.config/qwen38/sglang-dspark-v2.env`.

Same target as the 08-16 profile (TP2 BF16 weights/KV, FP32 GDN state,
262K context, 8 running requests, `extra_buffer`, flashinfer, static
verify, multimodal enabled) with two deliberate differences:

1. **Draft re-pinned** to `85ef153` via `/models/Qwen3.8-27B-DSpark-v2`
   (see §1).
2. **Mamba pin follows the 08-17 cookbook formula** (PR #35064):

   ```bash
   MAMBA_STATE_SLOTS="${MAMBA_STATE_SLOTS:-5}"        # extra_buffer
   MAX_MAMBA_CACHE_SIZE="${MAX_MAMBA_CACHE_SIZE:-$((MAX_RUNNING_REQUESTS * MAMBA_STATE_SLOTS))}"
   ```

   i.e. `8 × 5 = 40` at the defaults instead of 08-16's `8 × 13 = 104`. The
   engine divides the state pool by S alone; the speculative verify window
   (D = γ + 1 = 8) is sized separately. Folding D in (the 08-16 formula)
   over-provisions the GDN state pool and hands memory away from the KV
   pool. `MAMBA_STATE_SLOTS` maps one-to-one to the documented serving
   strategies: 5 = `extra_buffer` (low-latency), 4 =
   `extra_buffer_lazy` (high-throughput, no accuracy cost per the
   cookbook), 3 = `no_buffer`, 1 = radix cache disabled;
   `SGLANG_OPT_MAMBA_SKIP_DECODE_LOCK=1` frees one slot if ever combined.

**First-boot acceptance check (mandatory for v2):** the boot log's
`max_running_requests` line must equal the requested 8. If it is clamped,
restore the old formula with
`MAX_MAMBA_CACHE_SIZE=$((8 * (5 + 7 + 1)))` and file the observation
against the cookbook.

The rest of the launch is byte-for-byte the 08-16 flag set
(`--speculative-algorithm DSPARK`, `--speculative-draft-model-path
/models/RadixArk/Qwen3.8-27B-DSpark-v2`, `--speculative-dspark-block-size
7`, `--mamba-radix-cache-strategy extra_buffer`, `--kv-cache-dtype
bfloat16`, `--mamba-ssm-dtype float32`, `--attention-backend flashinfer`,
`-e SGLANG_RAGGED_VERIFY_MODE=static`, secure entrypoint, GPU power-cap
preflight, log archiving). The 08-16 backend switcher does not cover the
`-v2` container; switch by hand (`docker stop …-sglang` / `docker start
…-sglang-v2`).

**Cookbook cross-reference (new URL):**
<https://docs.sglang.io/cookbook/autoregressive/Qwen/Qwen3.8-27B.md>.
Notable for this card family (SM120): `--attention-backend flashinfer`
(`trtllm_mha` is SM100-only); MTP with FlashInfer requires a FlashInfer
build whose prefill `plan` accepts `uniform_q_len` (newer than
0.6.15.post1) — otherwise run spec on `--attention-backend triton`. DSpark
**does not take** `--speculative-num-draft-tokens`; its verify window is
`--speculative-dspark-block-size` (γ, auto-inferred from the checkpoint) +
1. The cookbook's MTP is EAGLE `3/1/4` (+ `--enable-linear-replayssm-spec`
on sm120) — an alternative to our in-image frozen-KV MTP path, not a
replacement. The cookbook's single-GPU grid (H200 / RTX PRO 6000 / RTX 5090
/ DGX Spark) validated all 36 Spec × Strategy × SSM-dtype combinations at
ISL 8192/OSL 1024 c1 — on our exact image, including the GB10 aarch64 build.

## 7. Validation gate (applies to every v2 first boot)

Cold boot, no other model container running, power caps verified by the
launcher preflight:

1. **Boot log:** `max_running_requests` == 8 (SGLang v2 — new check), no
   OOM/NCCL/verify-budget warnings, `Resolved architecture:
   Qwen3DSparkModel` (vLLM v2), aux `(5, 17, 29, 41, 53)` (vLLM v2).
2. **Probes:** text (xhigh default), tool call, image (single 1080p),
   streamed-vs-non-streamed byte-identity with `jq` parsing.
3. **Acceptance:** DSpark acceptance length/throughput vs the 08-16 profile
   at ISL 8192 / OSL 1024, c1 and c8 (both engines). The draft revision
   change is code-only (weights identical), so acceptance deltas isolate
   the engine/image/mamba-pin differences.
4. **Needle ladder:** 32K / 108K / 262K.
5. **8-agent concurrent soak** with the prefix-cache hit rate logged.
6. **KV pool:** SGLang v2 should report a *larger* available KV pool than
   the 08-16 profile at the same `mem-fraction-static` (the state pool
   shrank 104 → 40); confirm the 262K context still fits.
