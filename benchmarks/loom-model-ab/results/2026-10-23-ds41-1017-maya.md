## Protocol note — v3

The two shared partials below (FR-038, FR-040) are not an arm-specific weakness. The
visible v2 wire contract never says `agent_settled` must not emit `observe-event`
(it calls it a generic event whose payload is retained) or that a child exit emits
`terminate-child`; those rules lived only in the hidden reference, so every v2 arm
lost the same points. **Protocol v3** makes the visible contract state both rules
and changes nothing else (types, answer key, requirements and rubric scoring are
identical). This run was scored on **v2** and cannot be re-scored on v3: the model
never saw the v3 text. A like-for-like comparison needs a re-run of this arm and of
each comparison arm on v3. Rough effect: the two terminal-effect partials (FR-038,
FR-040) should disappear for a model that otherwise reasons as this one did, i.e.
discovery 24/26 → up to 26/26, but that is a prediction, not a measurement.

They sit outside the two-file scope and contradict the run's own SC-008/OOS-012 and the brief. The graph is 14 tasks (4 real + 10 ADR), the largest so far (Qwen v2: 8, GLM v10: 9).

3. **Serial decomposition.** T1→T2→T3→T4 are strictly serial on one file, and T4 is a catch-all hardening task.

## Run conditions and the contention check

Maya serves one request at a time and was shared with another heavy client (reclaw) for most of the preparation. `run-arm.sh` refused to prepare earlier attempts while the server was busy. This run started when the server was idle (0 active, 0 queued) and `server_idle_at_start: true` was recorded.

The ledger shows no foreign traffic: the server handled **177 requests** during the run; the run's own LLM calls total **179** (69 parent turns + 37 brainstorm + 27 specify + 29 architecture + 15 plan-alignment + 2 decompose). The server was idle at both ends. Server totals for the window: 14.0 M prompt tokens (13.6 M reused), 281,904 output tokens.
