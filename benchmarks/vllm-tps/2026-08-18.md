# vLLM TPS probe — desktop, 2026-08-18

A quick, **non-scientific** throughput probe of the desktop vLLM server, run
to answer "how fast is inference, and does the 350 W GPU power cap matter?"
It directly motivated the 350 → 450 W power-cap change (commit `719b669`,
`machines/desktop/default.nix`).

## Environment

- **Host**: desktop (192.168.0.80) — 2× RTX PRO 6000 Blackwell Workstation
  (96 GB), Ryzen 9 9950X, NixOS, driver 575.57.08-era stack, vLLM OpenAI API
  at `http://192.168.0.80:8000/v1`
- **Model**: `qwen3.8-27b` (BF16), TP=2, `gpu_memory_utilization≈0.975`,
  context 262144
- **Probe**: `probe.py` in this directory — one streamed chat completion,
  `temperature=0`, ~60-token prose prompt ("explain how a hash map works"),
  decode TPS = `(completion_tokens − 1) / (total − TTFT)`, usage from
  vLLM's final stream chunk

## Method caveats (why "non-scientific")

- Single stream, single short prompt, one run per cell. No warm-cache
  control, no concurrency, no long-context prefill test.
- **Self-interference**: the measuring session itself ran on the same GPUs
  (this is the box that serves pi), so every cell shares that background
  load. The 350-vs-450 W comparison is still valid *relative*, since both
  sides had it.
- Thinking tokens stream in the `reasoning` delta field (NOT
  `reasoning_content`); answer tokens in `content`. TTFT below is time to
  the first **answer** token, so with thinking on it includes the whole
  reasoning phase.

## Results

GPU power cap 350 W (pre-change):

| Run | Thinking | completion | TTFT | total | DECODE TPS |
|---|---|---|---|---|---|
| warmup | off | 64 | 0.25 s | 1.17 s | 68.2 |
| A | off | 512 | 0.13 s | 7.76 s | **67.0** |
| B | xhigh | 1500 | 3.93 s | 23.46 s | 76.8 (blended) |

GPU power cap 450 W (post-change):

| Run | Thinking | completion | TTFT | total | DECODE TPS |
|---|---|---|---|---|---|
| warmup | off | 64 | 0.08 s | 0.84 s | 82.9 |
| A | off | 512 | 0.06 s | 6.20 s | **83.3** |
| B | xhigh | 1500 | 3.15 s | 17.46 s | **104.7** (blended) |

Extra cells @ 450 W (thinking-phase timing):

| Run | Thinking | first answer token | total | DECODE TPS |
|---|---|---|---|---|
| re-run | xhigh | 4.81 s | 25.37 s | 72.9 |
| re-run | low | 2.51 s | 20.96 s | 81.2 |

## Findings

1. **The 350 W cap was hard-throttling.** Under load both cards sat pinned
   at 349.9 W / 100 % util. Raising the cap to 450 W bought
   **~+20–25 % decode throughput** (67 → 83 tok/s clean answer; 77 → ~105
   tok/s blended with xhigh thinking) for free.
2. **Prefill is effectively instant** for short prompts: ~0.06–0.25 s
   TTFT with thinking off.
3. **Thinking costs latency, not throughput.** xhigh spends 2.5–4.8 s
   reasoning before the first answer token; the answer then streams at the
   normal rate. Total time ≈ thinking time + tokens/~85.
4. **Thermals at 450 W are comfortable**: GPU0 73 °C / 421 W, GPU1
   61 °C / 395 W sustained — ~20 °C of headroom before throttle.
5. **The CPU is the hot spot, not the GPUs**: Ryzen package at 93.9 °C
   (Tcase throttle point ~95 °C) while doing modest work — it bakes in a
   chassis full of ~800 W of GPU heat. New CPU cooler ordered
   (2026-08-18); a hot CPU/VRM can erode PCIe signal margin, which matters
   for the Xid 79 history in `docs/runbooks/gpu-inference-crash-triage.md`.

## Re-running

```sh
python3 benchmarks/vllm-tps/probe.py --thinking off
python3 benchmarks/vllm-tps/probe.py --thinking xhigh --max-tokens 1500
```

If you want a *scientific* pass: vLLM's `benchmark_serving.py` (or
`vllm bench serve`) against the same endpoint — concurrency sweep,
input/output length matrix, and a long-context prefill cell.
